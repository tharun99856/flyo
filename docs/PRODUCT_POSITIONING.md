# Triply Product Positioning - Clear and Explicit

## The Full Story (Without Hiding the B2C Origin)

### Original Vision: B2C Modular Travel Planner

**What Triply Was Designed To Be:**

A consumer-facing travel planning platform where individual travelers:
1. Choose destinations or regions they want to visit
2. Select accommodation from available options (hotels, hostels, vacation rentals)
3. Pick attractions and experiences they want to include
4. See transparent, itemized pricing for each component
5. Assemble their trip from the pieces they want
6. Book the complete package

**Core Differentiators:**
- **Modular:** Not a fixed package tour or fully AI-generated itinerary
- **Transparent:** Clear pricing for each component, no hidden fees
- **Customer-controlled:** Traveler makes the choices, not an agent or algorithm
- **Flexible:** Mix and match accommodation tiers, activities, transport options

**Target User:** Independent travelers who want structure without rigidity, transparency without complexity.

---

### This MVP: Narrowed to B2B Agent Workflow

**Why the Pivot:**

After researching Flyo's B2B travel-operations platform, I realized:
1. Travel agents already prepare proposals for customers
2. The "modular choice with transparent pricing" experience could help agents and customers finalize proposals
3. A full B2C marketplace isn't needed to test if structured customization reduces friction
4. Flyo serves travel businesses, not end consumers
5. Building for agent workflows first might validate the core interaction before scaling to B2C

**What This MVP Tests:**

One specific workflow that transfers from B2C to B2B:
- Agent prepares a proposal with base options
- Customer reviews and customizes from agent-approved alternatives
- Price updates live (transparency from B2C idea)
- Customer submits structured change request
- Agent receives organized summary instead of scattered messages

**What's Preserved from B2C Vision:**
- Modular choice (pick your hotel, activities)
- Transparent pricing (see impact immediately)
- Customer control (choose within approved boundaries)

**What's Added for B2B Context:**
- Agent-approved options only (not open marketplace)
- Structured handoff to agent workflow
- Fits inside existing proposal process

## This Is NOT:

❌ **A claim that Triply was always B2B**
- It wasn't. It started as a B2C marketplace idea.

❌ **Abandoning the original vision**
- The B2C concept remains the long-term origin story

❌ **A complete integration with Flyo**

## Product Hypothesis (Explicit)

**For B2B (This MVP):**

**IF** travel agents send proposals to customers
**AND** customers want to request changes (upgrade hotel, swap activities)
**AND** those requests arrive as scattered messages requiring interpretation
**THEN** a structured customization interface with agent-approved options and live pricing
**WILL** reduce back-and-forth and help agents reach confirmed bookings faster

**Validation Required:**
1. Do agents experience this friction? (Ask Shubham)
2. Does Flyo already solve it? (Ask Shubham)
3. Would structured selections help? (Test with pilot agent)

---

**For B2C (Future Vision):**

**IF** independent travelers want to plan trips with flexibility
**AND** they find fixed packages too rigid and open-ended planning overwhelming
**AND** they value transparent pricing and modular choice
**THEN** a B2C platform where they assemble trips from curated components
**WILL** attract travelers who want structure without losing control

**Validation Required:**
1. Market size and willingness to pay
2. Supplier partnerships (hotels, activities)
3. Competition from Airbnb Experiences, Viator, Get Your Guide
4. Technology infrastructure (inventory, payments, bookings)

## Three Possible Paths Forward

### Path 1: B2B Integration with Flyo

**If Shubham Says:**
"This workflow isn't in Flyo, and agents complain about change requests."

**Next Steps:**
1. Pilot with 2-3 Flyo agents
2. Integrate with Flyo's proposal and booking workflow (API/webhook)
3. Validate reduction in back-and-forth messages
4. Measure time-to-booking and conversion rate
5. Discuss white-label, partnership, or acquisition

**Timeline:** 3-6 months to validated integration

---

### Path 2: B2C Marketplace Build

**If Shubham Says:**
"Flyo already handles this, but the B2C concept is interesting."

**Next Steps:**
1. Research B2C travel planning market
2. Validate demand with potential customers
3. Build supplier partnership network
4. Add inventory, payments, booking confirmation
5. Launch regional pilot (e.g., Goa/Kerala)

**Timeline:** 12-18 months to beta launch

---

**If Shubham Says:**
"The workflow is useful, but Flyo can't integrate right now. What about white-label?"

1. Build standalone agent-facing proposal tool
2. Agencies use it alongside Flyo (not integrated)
3. Prove value through usage and feedback
4. Revisit integration when Flyo roadmap allows
5. Potentially serve non-Flyo agencies as well

**Timeline:** 6-9 months to pilot launch

## FAQ: Common Objections and Responses

### "Why should I care about your B2C idea?"

**Response:**
"You shouldn't—yet. The B2C marketplace is a long-term vision. This MVP tests whether the core interaction (modular choice + transparent pricing) reduces friction in your agents' workflows. If it doesn't, I won't waste your time with the bigger vision."

---

### "This feels like you're trying to build Flyo's features."

**Response:**
"Definitely not the intent. I don't have deep knowledge of Flyo's current capabilities. I built this to ask: does this workflow already exist, and if not, is it a pain point? If Flyo handles it well, I want to learn how. If there's friction, I want to understand where."

---

### "Why didn't you just build the B2C product?"

**Response:**
"Because building a full B2C travel marketplace requires supplier partnerships, inventory management, payment processing, and significant capital. Testing one workflow with sample data validates the interaction design before I commit to that infrastructure investment."

---

### "How do I know you won't pivot away from B2B if this works?"

**Response:**
"Fair concern. The honest answer: I'm exploring where the best product-market fit is. If agents using Flyo have this pain point and Triply solves it, B2B could be the primary path. If B2B doesn't work but consumer demand is strong, B2C might make more sense. I'm not locked into either. What matters is solving a real problem."

---

### "What do you want from Flyo—money, acquisition, partnership?"

**Response:**
"Right now, I want validation and feedback. If this workflow is useful and Flyo wants to integrate, we can discuss partnership, licensing, or acquisition. If it's not useful, I want to understand what problem agents actually face. Business terms come after product-market fit is established."
